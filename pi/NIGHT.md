# Pi Night Queue

Ночной режим обрабатывает **только** открытые GitHub Issues с меткой `agent:night` и для каждой задачи запускает существующую команду `/i #N`. Планирование, модели, subagents, проверки и review остаются внутри `/i`; отдельный workflow реализации не создаётся.

## Использование

В локальном checkout нужного GitHub-репозитория после обновления dotfiles и `/reload`:

```text
/night start       # до 8 часов
/night start 4     # до 4 часов
/night status
/night stop        # не запускает новые задачи, текущая /i завершается
```

Для подготовки очереди:

```sh
gh label create agent:night -R OWNER/REPO --description "Approved for unattended Pi /i execution" --color 6F42C1
gh issue edit 98 -R OWNER/REPO --add-label agent:night
```

Метка означает **явное разрешение на работу над конкретным Issue**. Ставьте её только на задачи с понятными требованиями, без продуктовых решений и без необходимости менять production. Метка `agent:blocked` или `blocked` исключает задачу. Очередь сортируется по возрастанию номера Issue (не является GitHub Projects priority). Максимум 100 Issues за запуск.

## Поведение

- Запускает **одного** worker на задачу (без параллельного исполнения).
- Создаёт отдельный worktree рядом с корневым checkout: `../REPO-night-worktrees/issue-N`; ветка `agent/night/issue-N`.
- Запускает Pi в `--mode json` с исходной командой `/i #N` и ограниченным разрешением: коммиты, push только task-ветки, draft PR; **не** merge/deploy/production/destructive actions.
- Проверяет `agent_settled`, model/extension errors, явный `workflow_status: blocked`. При техническом сбое повторяет попытку максимум один раз в той же сессии и worktree.
- Не делает автоматический `git add`: если агент оставил изменения без коммита, задача считается blocked.
- При чистом worktree и наличии коммитов проверяет `git diff --check`, push ветки и создаёт **draft PR**. Уже существующие PR повторно не создаёт; исходные Issues не закрывает.
- При неустранимой ошибке фиксирует blocker и переходит к следующему Issue. Когда заканчивается временное окно, **новые** Issues не запускаются; текущую задачу не обрывает.
- `/night stop` — мягкая остановка: текущий `/i` дорабатывает. Рабочие директории, логи и Pi-сессии сохраняются для диагностики и восстановления; автоматически не удаляются.
- На macOS фоновой процесс оборачивается в `caffeinate -is`, но закрытая крышка ноутбука и выключение питания всё равно могут прервать выполнение.

**Важно:** ограничения на merge/deploy/production в этой версии выражены инструкциями агенту, а не непроходимым sandbox. Запускать только задачи, для которых доверяешь установленным permissions и содержимому репозитория. Ответственный за принятие PR — человек.

## Состояние и диагностика

Для обычного checkout:

```text
.git/pi-night/state.json
.git/pi-night/lock.json                # существует во время запуска
.git/pi-night/stop                     # мягкий stop-request
.git/pi-night/logs/N-A.jsonl           # структурированные Pi events
.git/pi-night/logs/N-A.stderr.log
.git/pi-night/sessions/N/              # независимая Pi-сессия Issue
```

Состояние остаётся локальным, не коммитится. После аварии следующий запуск переиспользует worktree и (при наличии сохранённой сессии) продолжает ту же Pi-сессию. Наличие удалённой ветки без PR требует ручной проверки: night не перезаписывает её.

## Требования и тесты

Необходимы `git`, `gh` с авторизацией (`gh auth status`), `pi` и Node.js версии, поддерживаемой текущим Pi. Команда регистрируется через глобальный discovery файла `~/.config/pi/extensions/night.ts` (Stow). Фоновый запуск стартует из того репозитория, в котором был вызван `/night`.

```sh
node --test pi/tests/night-queue.test.mjs
```

Этот тест использует временный bare Git remote и поддельные `gh`/`pi`: проверяет выбор меток, реальный Git worktree/commit/push, вызов `/i` и параметры draft PR. Проверка на живых подписочных моделях и настоящем GitHub API отдельно **не выполнялась**.
